# DOMAIN

## Смысл системы

Система моделирует поведение пользователя как последовательность событий и состояний, а не как набор функций бота.

Основная идея:  
**поведение пользователя существует во времени и выражается через события выполнения.**

## Модель предметной области

В системе нет “задач” в классическом смысле. Есть три типа доменных объектов:

- сущности состояния (Habit, Goal)
- сущности событий (Completion)
- вычисляемые состояния (status, progress)

## Habit как устойчивое намерение

Habit — это не действие, а **описание ожидаемого поведения**.

Она не “выполняется”, она существует как правило:
> “пользователь должен регулярно совершать действие”

Важно:  
Habit сама по себе не несёт факта выполнения.

## Completion как событие системы

Completion — это **факт, зафиксированный в момент времени**.

Она не изменяется и не пересчитывается.

Это ключевая идея:

> система хранит не состояние, а историю событий

## Goal как вычисляемое состояние

Goal — это не объект, который “обновляется вручную”.

Это **результат вычисления над событиями и прогрессом**.

Её состояние не хранится напрямую, а выводится:

- из current / target
- из времени (deadline)
- из динамики изменений

## Принцип работы системы

Система не “управляет данными”, а:

1. фиксирует события (Completion)
2. хранит намерения (Habit)
3. вычисляет состояния (Goal status)
4. строит историю поведения пользователя

## Инварианты домена

- события неизменяемы после создания
- состояние цели не является источником истины (оно выводится)
- привычка не может “завершиться” — она только существует
- данные всегда интерпретируются через время

## Ключевая идея

HG-Bot-Tracker — это не система управления задачами.

Это система, которая:
> превращает действия пользователя во временную модель поведения
